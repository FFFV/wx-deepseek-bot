# DeepSeek × 个人微信

把 DeepSeek 接进你本机的微信：能读消息、回消息、发表情、看图片、联网查资料、记住聊过的事。

运行在一台 Windows 电脑上，驱动**真实的微信客户端**。不是公众号，不是网页版，也不需要手机。

> 微信没有开放个人号的机器人接口，本项目通过「读本地数据库 + 驱动客户端界面」实现。
> 它依赖微信客户端本身，微信升级后可能需要适配。

**它不是一个在线服务**：你需要一台常开的 Windows 电脑、一个已经登录的微信、一个 DeepSeek API Key。

## 一、功能一览

| 功能 | 说明 | 默认 |
|---|---|---|
| 自动回复 | 私聊会回；群里默认只回 @ 你的 | 开 |
| 人设 | 用 `persona.txt` 定义说话风格，可换成任何角色 | 开 |
| 分条发送 | 多行回复拆成几条发出去，像真人连打几条 | 开 |
| 表情包 | 模型按需发本地图片，一条最多一张 | 开 |
| 颜文字 | 按情绪贴颜文字，有概率和冷却 | 开 |
| 识图 | 能看对方发来的图片 | 开 |
| 联网搜索 | 需要时查最新信息 | 开 |
| 长期记忆 | 记住每个人的事，会话闲置后自动摘要，每天整理一次 | 开 |
| 好感度 | 0~100 分，影响语气，可以查询 | 开 |
| 主动说话 | 没被 @ 也可能自己接一句（实验功能，需灰度名单） | 关 |
| 多开微信 | 钉死一个微信号和它的窗口，不会读错号、发错号 | 开 |

## 二、运行环境

| 项 | 要求 |
|---|---|
| 系统 | **Windows 10 / 11**（Linux、macOS 跑不了） |
| 微信 | **4.1.12 或更高**，已登录，**窗口保持打开** |
| Python | **64 位 3.10+**，推荐 3.12 |
| 网络 | 安装依赖需要联网（约 350 MB）；运行时需要能访问 `api.deepseek.com` |
| API Key | <https://platform.deepseek.com/api_keys> |

三点说明：

- **32 位 Python 读不了 64 位微信的内存**，这是最常见的失败原因。
- 微信窗口最小化或关掉，程序就读不到库、也发不出去。
- 运行期间**不能碰鼠标键盘**（原因见[第九节](#九使用须知)）。

## 三、安装

**第 1 步 · 装 Python**

装一个 **64 位 Python 3.12**，安装时勾选 *Add to PATH*：<https://www.python.org/downloads/windows/>

**第 2 步 · 双击 `install.cmd`**

它会自动：找 Python → `pip install -r requirements.txt` → 生成 `config.json`。

国内网络慢的话，在命令行里用镜像自己装：

```bat
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

**第 3 步 · 先跑一次自检，拿到自己的 wxid**

双击 `check.cmd`：

```
1) 检查 DeepSeek …      ❌ 失败：没有配置 DEEPSEEK_API_KEY   ← 还没填，正常
2) 检查微信数据库 …      ✅ 账号：xxx
   ✅ 读到 12 个会话（示例）：
      wxid_abc123...        未读=0  ...
      12345678901@chatroom  未读=3  ...
3) 检查识图 …            ✅
4) 检查发送通道 …        ✅
```

`wxid_` 开头是个人，`数字@chatroom` 是群。把**你自己的 wxid** 记下来。

**第 4 步 · 填配置，再自检一次**

打开 `config.json`，至少改这两处：

```json
"api_key": "sk-...",          // 或者设环境变量 DEEPSEEK_API_KEY（更安全）
"whitelist": ["wxid_xxx"]     // 填你自己的 wxid；留空 = 回复所有人的私聊
```

保存后再双击 `check.cmd`，四项全绿就可以双击 `run.cmd` 开跑了。

## 四、配置说明

所有配置都在 `config.json`，改完重启程序生效。

### 必填

| 字段 | 默认 | 说明 |
|---|---|---|
| `api_key` | `""` | DeepSeek API Key。也可以设环境变量 `DEEPSEEK_API_KEY`，环境变量优先 |
| `model` | `deepseek-flash` | 聊天模型。可选 `deepseek-v4-pro`（更贵更慢，复杂推理更准） |

### 人设

| 字段 | 默认 | 说明 |
|---|---|---|
| `system_prompt` | 一句通用提示 | 内联人设，`system_prompt_file` 为空时才用 |
| `system_prompt_file` | `persona.txt` | 人设文件，设了就覆盖 `system_prompt` |

### 回复

| 字段 | 默认 | 说明 |
|---|---|---|
| `max_tokens` | `800` | 单条回复的最大长度 |
| `temperature` | `1.0` | 越高越随机 |
| `thinking` | `false` | 思考模式。开着更慢更贵，聊天场景建议关 |
| `timeout` | `60` | 单次请求超时（秒） |
| `reply_split` | `true` | 多行拆成几条发 |
| `reply_split_max` | `5` | 最多拆几条，超了并到最后一条 |
| `rate_limit` | `50` | 每个会话每小时最多回几条 |

### 会话与记忆范围

| 字段 | 默认 | 说明 |
|---|---|---|
| `history_turns` | `6` | 记住最近几轮对话（1 轮 = 一问一答） |
| `session_ttl` | `1800` | 多久没说话就清空对话历史（秒） |

### 群聊与黑白名单

| 字段 | 默认 | 说明 |
|---|---|---|
| `group_mode` | `at` | `at` 只回 @ 你的 / `all` 每条都回（容易刷屏）/ `off` 不理群 |
| `my_names` | `[]` | 群里 @ 你时显示的名字。昵称和群名片不一致就都写上 |
| `whitelist` | `[]` | 只回复这些会话。**留空 = 不限制，会回复所有人** |
| `blacklist` | `[]` | 永不回复这些会话，优先级高于白名单 |
| `developer_ids` | `[]` | 开发者本人的 wxid / 昵称，命中后语气更亲近 |

### 表情与颜文字

| 字段 | 默认 | 说明 |
|---|---|---|
| `sticker_dir` | `stickers` | 表情图片目录。文件名就是表情名，支持 gif/png/jpg/webp |
| `sticker_max` | `1` | 一条回复最多带几张表情 |
| `kaomoji_enabled` | `true` | 是否贴颜文字 |
| `kaomoji_rate` | `0.5` | 模型标了情绪后，真正贴出来的概率 |
| `kaomoji_cooldown` | `300` | 同一个会话多少秒内最多贴一次 |

### 识图

| 字段 | 默认 | 说明 |
|---|---|---|
| `vision_enabled` | `true` | 是否识别图片 |
| `vision_model` | `deepseek-flash` | 视觉模型 |
| `vision_detail` | `low` | `low` 省 token；要看截图里的字用 `original` |
| `vision_max_per_hour` | `10` | 每个人每小时最多识几张 |
| `vision_image_ttl` | `60` | 图片和随后那条消息最多隔几秒算同一件事 |
| `vision_max_side` | `1300` | 上传前把图压到这个边长内 |
| `image_paste_wait` | `3` | 发图片时，粘贴后等几秒再回车 |

### 联网搜索

| 字段 | 默认 | 说明 |
|---|---|---|
| `web_search_enabled` | `true` | 是否允许联网 |
| `web_search_count` | `3` | 每次搜几条结果 |
| `web_search_per_hour` | `6` | 每个人每小时最多搜几次 |
| `web_search_rounds` | `2` | 一轮对话里最多连续搜几轮 |

### 长期记忆

| 字段 | 默认 | 说明 |
|---|---|---|
| `memory_file` | `memory.json` | 记忆落盘文件。留空 = 只存内存，重启就忘 |
| `memory_traits` | `30` | 每个人最多存几条印象 |
| `memory_recall` | `6` | 每条消息注入几条最相关的印象 |
| `memory_recall_chars` | `400` | 注入印象的总字数上限 |
| `memory_recent` | `3` | 每人最多留几轮最近对话 |
| `memory_moments` | `6` | 每人最多存几条"瞬间记忆" |
| `summary_enabled` | `true` | 会话闲置后压成摘要 |
| `summary_after` | `600` | 闲置多少秒后压缩 |
| `summary_keep` | `10` | 每人最多留几条摘要 |
| `summary_inject` | `2` | 每次注入几条摘要 |

| `reflect_hours` | `24` | 每隔多少小时整理一次 |
| `reflect_active_days` | `7` | 只整理最近几天说过话的人 |

### 主动说话（实验）

| 字段 | 默认 | 说明 |
|---|---|---|
| `proactive_enabled` | `false` | 总开关 |
| `proactive_ids` | `[]` | 灰度名单：群名、群号、群友昵称、wxid 都行。**留空 = 谁都不启用** |
| `proactive_chance` | `0.15` | 每条消息有多大比例会去"想一下" |
| `proactive_min_gap` | `600` | 同一会话两次主动发言最少间隔（秒） |
| `proactive_max_per_hour` | `3` | 每个会话每小时最多主动几次 |

### 运行与维护

| 字段 | 默认 | 说明 |
|---|---|---|
| `dry_run` | `false` | `true` 时只打印不发送，记忆也不落盘 |
| `log_file` | `wxbot.log` | 日志文件 |
| `log_max_bytes` | `2097152` | 单个日志上限，超了轮转。`0` = 不轮转 |
| `log_backups` | `5` | 留几份历史日志 |
| `image_keep_days` | `7` | 识图临时图片保留几天 |
| `image_keep_max` | `200` | 临时图片最多留几张 |

| `wx_debug` | `false` | 打开底层库的调试日志（排错用） |

### 多开微信（两个微信同时登着）

电脑上同时登着两个及以上微信号时，程序默认靠"哪个库最近改过"猜账号，两个号都活跃就会猜错。用这两个字段钉死一个：

| 字段 | 默认 | 说明 |
|---|---|---|
| `wx_account` | `""` | 只认这个微信号。填 **wxid**（如 `wxid_abc123`）或账号目录名（如 `wxid_abc123_e1f1`）。留空 = 自动挑，可能挑错 |
| `wx_hwnd` | `0` | 发消息用哪个微信窗口。`0` = 自动；发现回错了号再手工填 |

账号目录名和窗口句柄都可以用 `run.cmd --wx-list` 查出来：

```
账号目录：
  wxid_abc123_e1f1
  wxid_def456_9a8b

微信窗口：
  [1] hwnd=67180  pid=12940  1386x1001
  [2] hwnd=132718 pid=20884  1000x800
```

填法：

```json
"wx_account": "wxid_abc123",
"wx_hwnd": 0
```

`wx_hwnd` 平时留 `0` 就行——程序会先按"谁打开着这个账号的数据库"去对窗口，对不上才退回面积最大的那个，并在日志里写明。换过微信窗口以后句柄会变，所以只有自动匹配不准时才手工填。

**两个微信号只留一个在跑，就不用管这两个字段。**

## 六、使用说明

### 6.1 人设

人设写在 `persona.txt` 里，就是一段给模型的设定，可以随意改成任何角色。

```
persona.txt          仓库自带的通用示例（小鲸鱼）
persona.local.txt    你自己改的那份（不会提交，建议复制一份来改）
```

改法：

```bat
copy persona.txt persona.local.txt
```

然后把 `config.json` 里的 `system_prompt_file` 改成 `"persona.local.txt"`。

人设里定义了一套**标记协议**，程序靠这些标记工作。改人设时**这五组规则建议保留**：

| 标记 | 作用 | 例子 |
|---|---|---|
| `[记住:内容]` | 记进这个人的长期记忆 | `[记住:对花生过敏]` |
| `[好感:+N]` | 调整好感度 | `[好感:+5 被夸]` |
| `[回忆:内容]` | 记一条她自己的感受 | `[回忆:他说谢谢我一直陪他]` |
| `[颜:情绪]` | 贴一个颜文字 | `[颜:害羞]` |
| `[表情:名字]` | 发一张 `stickers/` 里的图 | `[表情:开心]` |

标记本身不会出现在聊天里，程序会把它们抠掉。模型自己发明的其它标签（比如 `[想念:]`、`【心情：…】`）也会被删掉，不会发进聊天。

### 6.2 群里什么时候回

| 场景 | 行为 |
|---|---|
| 私聊 | 默认每条都回（受白名单限制） |
| 群聊，`group_mode: at` | 只回 @ 你的 |
| 群聊，`group_mode: all` | 每条都回（不建议） |
| 群聊，`group_mode: off` | 完全不理会 |

`my_names` 要写全：群里 @ 你时可能显示昵称、备注或群名片，不一样就都加上。

### 6.3 表情包

把 `.gif` / `.png` / `.jpg` / `.webp` 放进 `stickers/`，**文件名就是表情名**：

```
stickers/开心.gif
stickers/无语.png
stickers/晚安.gif
```

重启后启动日志会打印「可用表情 N 个：…」，模型想发时会输出 `[表情:开心]`，程序单独发一条图。

一条回复最多一张（`sticker_max`）。**表情版权自己负责**，别用有商用限制的素材。

### 6.4 识图

对方发图后**紧接着的那条消息**（默认 60 秒内）会被一起看。

首次使用需要"喂"一次密钥：**在微信里点开任意一张大图看几秒**，程序会抓到图片的解密密钥并缓存，之后就不用管了。

没抓到密钥时，取图最多等 20 秒——等不到就先回文字，不会一直卡着不说话。

如果图片是 `.wxgf`（微信 4.x 的私有容器），还需要 ffmpeg —— `pip install imageio-ffmpeg`，或者自己装 ffmpeg 到 PATH。

### 6.5 联网搜索

模型判断需要最新信息时才会搜索，普通闲聊不搜。每人每小时最多 6 次，一次对话最多连续搜两轮。

### 6.6 记忆

记忆分四层，全自动，不需要手动管理：

| 层 | 存什么 | 容量 | 什么时候产生 |
|---|---|---|---|
| 对话历史 | 最近的原文对话 | 6 轮 / 30 分钟 | 每条消息 |
| 会话摘要 | 这段聊了啥（1~2 句） | 每人 10 条 | 会话闲置 10 分钟 |
| 印象 | 这个人的事实，带时间 | 每人 30 条 | 模型标 `[记住:]` |
| 每日反思 | 合并重复、消解矛盾 | — | 每 24 小时 |

每个人的档案是**按人**存的：同一个人在不同群、私聊里，认得都是同一份。

记忆越存越多，但**每条消息只注入最相关的几条**（默认 6 条、400 字以内），所以不会越聊越贵。

想让她忘掉某个人：**先停掉程序**，编辑 `memory.json`，删掉 `profiles` 里对应那条，再启动。

### 6.7 好感度

每个人有一个 0~100 的分，初次见面 **50**，影响她说话有多亲近：

| 分数 | 档位 | 语气 |
|---|---|---|
| 0–20 | 冷淡 | 客气、简短、不卖萌、不主动 |
| 21–40 | 客气 | 礼貌但有距离 |
| 41–60 | 眼熟 | 正常聊天，偶尔卖萌 |
| 61–80 | 熟络 | 撒娇、开玩笑、主动问近况 |
| 81–100 | 亲密 | 像老朋友，说心里话、会惦记 |

涨跌由模型标 `[好感:N]` 触发，闸门在程序侧：单次最多 ±10、每天最多 +30 / -40、总分 0~100。

### 6.8 主动说话（实验功能）

打开后，**没被 @ 她也会偶尔自己接一句**，但只在 `proactive_ids` 名单里生效。

```json
"proactive_enabled": true,
"proactive_ids": ["某个群的名字", "wxid_xxxxxxxx"]
```

设置项：

- `proactive_chance` 只有一部分消息会真的去"想一下"（控制成本）
- `proactive_min_gap` 两次主动发言至少隔多久（默认 10 分钟）
- `proactive_max_per_hour` 每小时最多几次（默认 3）

她只在**值得接话**时开口：有人问了个她能答的问题、聊到她懂的东西、群里冷清需要热一下。单纯的笑声、情绪发泄、别人的私事，她会保持安静。

触发点永远是别人的一条消息，不会定时凭空找人聊天。

### 6.9 多开微信

同时登着两个微信号时，先跑一次：

```bat
run.cmd --wx-list
```

把打印出来的账号目录名（或它的 wxid 前缀）填进 `config.json` 的 `wx_account`，重启程序。启动日志里出现「已锁定微信账号：…」就说明钉住了，另一个号的消息不会被读、也不会被用来发消息。

如果发现回复出现在错误的微信号上（日志里会有「检测到 N 个微信窗口……先按面积最大的那个发」的警告），把 `--wx-list` 里对应的 `hwnd` 填进 `wx_hwnd`。

**不用锁定也能跑**：只登一个微信号时，程序自动选，不需要配这两项。

### 6.10 命令

发下面这些词，会走程序自带逻辑（不经过模型）：

| 命令 | 作用 |
|---|---|
| `重置` / `清空记忆` / `新对话` | 清空当前会话的对话历史，**档案保留** |
| `好感度` / `好感查询` | 回复准确分数，比如 `好感度 62/100（熟络）｜今天 +5` |

## 八、常见问题

| 现象 | 原因 / 解决 |
|---|---|
| `找不到配置文件 config.json` | 先复制一份：`copy config.example.json config.json` |
| `还没有 DeepSeek API Key` | 填 `config.json` 的 `api_key`，或设环境变量 `DEEPSEEK_API_KEY` |
| `未检测到 Weixin.exe` | 微信没开，或者进程名不是 Weixin.exe |
| `数据库无可用密钥` | Python 不是 64 位 / 权限不够 / 多账号选错（用 `wx_account` 锁账号） |
| `ImportError: win32ui` | pywin32 没装好，重装 `pywin32` 或跑它的 `pywin32_postinstall.py` |
| `ModuleNotFoundError: No module named 'wechatauto'` | 依赖没装，双击 `install.cmd` 或 `pip install -r requirements.txt` |
| 发送返回失败但没报错 | 微信窗口被最小化或被别的窗口盖住 |
| 回了自己的消息 | `sender_username` 没解析出来，把 `my_names` 和白名单配好 |
| 识图一直没反应 | 图片没解密：在微信里点开任意一张大图看几秒 |
| 发图之后半天不回 | 取图卡在等密钥。程序最多等 20 秒就先回文字；在微信里点开一张大图把密钥喂上即可 |
| `400 … unsupported image` | 图片是 `.wxgf` 容器，装 `imageio-ffmpeg` |
| 回复偶尔要 20 多秒 | 建连时碰上了不响应的 CDN 节点，程序会在几秒内自动换一个地址；日志里会写原因 |
| 群里一直不回 | 没 @ 你。要么 @ 一下，要么把 `group_mode` 改成 `all`（不建议） |
| 刚启动不回消息 | 先看日志有没有「已锁定微信账号」。多开微信选错账号时会读另一个号的库（`run.cmd --wx-list` 查，填 `wx_account` 锁死）；启动卡在「正在打开微信数据库」说明在重算密钥，锁账号可避免 |
| 回复发到了另一个微信号上 | 多开窗口选错。`run.cmd --wx-list` 查 hwnd，填进 `wx_hwnd` |
| 发送要等很久 / 一直不回 | 日志里搜「已经等了 N 秒还没发出去」，能看出卡在模型还是卡在发送 |
| 程序一闪就退 | 用 `run.cmd` 启动（窗口会停住）；直接双击 `python` 脚本看不清报错 |

**日志**：`wxbot.log`，单文件满 2 MB 自动切一份，最多留 5 份。排错时先看最后 50 行。

## 九、使用须知

**1. 运行期间不能碰鼠标键盘。**

发消息是靠模拟输入打进微信输入框的，发送那一下会抢焦点。所以：

- 最好用一台闲置电脑或虚拟机
- 发送期间别打字、别点别的窗口
- 电脑锁屏时发不出去

**2. 微信必须开着、且窗口不能最小化。**

程序读的是微信的本地数据库，发消息驱动的是微信窗口。关掉窗口 = 收不到也发不出。

**3. 第一次用，先把白名单填上你自己。**

`whitelist` 留空 = 不限制，任何给你发私聊的人都会收到机器人的回复。先去 `config.json` 里填自己的 `wxid`。

**4. 会产生 API 费用。**

文字聊天很便宜（每条不到一分钱），联网搜索贵一些。具体看 DeepSeek 的计费页。长期挂着建议设好 `rate_limit`。

**5. 聊天内容会发给 DeepSeek。**

包括你让它看的图片。介意的话别在敏感对话里用。

**6. 只支持 Windows。**

Linux / macOS 上跑不了机器人本体（依赖 UIA 和 Windows API）。

**7. 需要给很多人用、要长期稳定？**

那应该用公众号或企业微信，不是这个项目。
